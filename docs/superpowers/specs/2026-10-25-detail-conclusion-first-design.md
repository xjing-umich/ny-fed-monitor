# 首期 UX 第 4 步：详情页先结论后证据（并入第 3 步的详情页部分）

**日期：** 2026-10-25
**状态：** 用户已审阅通过（2026-10-25），并按复查结果精简三处：去掉“最大持有人”一句、锚点只在 ≥768px 吸顶、投资人页名字行放到 PR 2 最后可砍。范围由用户 2026-10-24 选定（A + C + D 的详情页部分，B 补名字）；结论带做法由用户选定（复用现有标尺）。投资人页名字范围采用推荐项（用户未作答，见 §5）。
**上游：** `2026-10-19-ux-phase1-roadmap.md` 第 3、4 步；改版提案 https://claude.ai/artifact/V52oFBFHX3o5mahrqtAp2y（“关键页面改版 › 个股页”示意）；第 2 步 spec `2026-10-23-data-consistency-design.md`。
**代码基线：** `db-foundation` @ `c64a25a`（2026-10-23，含 #221、#222、#223）。
**目标日期：** 11/10 前合并；11/10–11/14 冻结，留给 Q3 报告上线。

## 一、为什么做

Q3 报告和 newsletter 带来的新读者，多数会落在个股页。按提案的审查，新访客应该 10 秒内说得出这页的结论；但现在个股页首屏只有一枚徽章和三个数字，价值标尺排在“生意质量”之后，持有人在更下面。最有差异化的东西（击球区筛选器）藏在“个股 › 按价值带”二级标签里。颜色上，绿色同时表示估值便宜、加仓、净买入，读者分不清哪种绿是信号。

## 二、现状（2026-10-24 线上）

| 页面 | 区块顺序 |
|---|---|
| 个股页（AAPL） | 标题 + 徽章 → 关键数字（现价 / 持有人数 / 合计市值）→ 生意质量 → 估值（标尺、一句结论、方法与数字折叠、价格在押注什么）→ 持有人（说明行、本季动作、申报季说明、趋势、表、文字摘要折叠）→ 共同持有 → 引导 → 外链 → 来源 → 订阅 |
| 投资人页（巴菲特） | 标题 + 关键数字 → 本季四格 + 清仓名单 → 隐含预期一句 → 估值姿态 → 独门重仓 → 持仓表 → 关于（折叠）→ 引导 → 来源 |
| 顶部导航 | 首页 / 超级投资者 / 个股 / 学习 |

相关代码：`src/app/[lang]/stocks/[ticker]/page.tsx`（`EntityPage` + `HoldersTable`）、`src/components/valuation/EarningsPowerFloorCard.tsx`（导出 `ValueBandGauge`，内部 `ValueSpine` 渲染标尺与结论句，下方 `<details>` 是方法与数字）、`src/components/entity/EntityPage.tsx`、`src/lib/nav.ts`、`src/components/shell/TopNav.tsx` / `AppShell.tsx`（顶栏 sticky，桌面 60px、手机 56px）。

## 三、设计

### 1. 个股页结论带（A）

结论带紧跟标题，取代个股页现在的关键数字行（`keyFacts` 传空数组，`EntityPage` 不渲染该行）。两栏：≥768px 左右并排（左宽右窄约 3:2），窄屏上下堆叠。

**左栏：价格相对价值带**

- 第一行：现价（带日期与来源，过期置灰，沿用 `fmtPriceFact` / `priceFactNote`）；已确认便宜时在现价后面跟“安全边际 77%”（沿用现在 `marginShown` 的条件）。
- 标尺：现有 `ValueBandGauge`，不重画。
- 一句结论：沿用估值卡里现在那句（`priceVsBandAndIv` / `priceVsBand` / 单法句），不改文字。
- 特殊情况：
  - 未评估（无 verdict）：不画标尺，写“未评估”加 `valuationLabel` 的原因。
  - 拆股覆盖过期（`splitCoverageStale`）：写现有的“估值暂停”提示。
  - 控股公司 SOTP（`holdcoNotAssessable && holdcoSotp`）：写 SOTP 中枢一行，标尺省略，细表留在下方估值区块。

**右栏：谁在持有**

- “27 位持有 · 合计 $76.77B”（从持有人表上方移来）。
- 本季动作一行 `QuarterMovesLine`（从持有人表上方移来）。
- 持有人趋势 `HolderTrend`（从持有人表上方移来）。

不写“最大持有人”一句：持有人表第一行和文字摘要里已经有这个事实。

**移走后不重复：** 持有人表上方只保留申报季说明（它解释的是表里的季度标签，必须贴着表）。估值卡不再渲染标尺和结论句（见 §3）。标题徽章保留（它是标尺结论的一词版，属于标题行，不算重复事实）。

新组件 `src/components/stocks/StockConclusionBand.tsx`（RSC），只接收页面已经算好的值，不读数据。

### 2. 区块重排与页内锚点（A）

新顺序：

1. 标题 + 徽章
2. 结论带
3. 页内锚点导航
4. 持有人（`#holders`）：申报季说明、持有人表、文字摘要折叠
5. 估值与方法（`#valuation`）：方法与数字（折叠）、TTM 口径、价格在押注什么、“内在价值怎么读”
6. 生意质量（`#quality`）
7. 共同持有（`#co-owned`，有数据时）
8. 引导、外链、来源（`#sources`）、订阅

锚点导航：一行普通 `<a href="#…">`。≥768px 时 `position: sticky`，`top` 等于顶栏高度（768–1023px 为 56px、≥1024px 为 60px）；<768px 不吸顶，只是结论带下方一行链接（手机上顶栏已常驻 56px，再常驻一条会挤占阅读空间），可横向滚动。各区块加 `id` 和 `scroll-margin-top`（顶栏高度 + 导航高度）。零 JS：不做“当前区块高亮”（需要客户端代码，不在本步）。没有数据的区块不出现在导航里。

### 3. 估值卡拆成两部分（A 的配套）

`EarningsPowerFloorCard` 增加 `part?: "all" | "summary" | "details"`，默认 `"all"`（行为不变）。

- `"summary"`：大号读数 + 标尺 + 结论句（结论带左栏用）。
- `"details"`：方法与数字折叠及其余明细（估值区块用）。

两部分从同一份计算结果渲染，数字不重复计算。只有个股页用到这个卡（核对过调用方），其他调用方不受影响。

### 4. 顶部导航加“击球区”（C）

主导航改为：首页 / 超级投资者 / 个股 / **击球区** / 学习。“击球区”链到 `/stocks/screener?view=strike_zone`（中文 `/zh/stocks/screener?view=strike_zone`），手机抽屉同一份列表（`src/lib/nav.ts` 单一来源）。当前项高亮：路径为 `/stocks/screener` 时高亮“击球区”而不是“个股”。个股子导航里的“按价值带”保留。

### 5. 投资人页本季动作带名字（B，补齐）

四格计数下方现在只有“清仓 1：Constellation Brands”。改为最多两行：

- “● 新建 1：D R Horton · 低于内在价值”
- “○ 清仓 1：Constellation Brands”

每类最多 3 个名字，其余“另 k 只”；名字后跟该股的估值说法（`valuationLabel` 文字，灰色小字，不用胶囊，避免首屏一片色块；无估值不写）。加仓、减仓只给个数，名字在持仓表的动作标里。数据来自页面已加载的 `longChanges` 和 `verdicts`，不新增查询。

用户未回答这一项的范围问题，按推荐项执行；如需改为四类都列名字，只改这一节。这一项与主线关系最弱，放在 PR 2 最后做，时间紧可以砍掉，不影响其他部分。

### 6. 颜色语义与动作字形（D，详情页相关部分）

**估值色阶只给估值用。** 令牌 v2 已在 `globals.css`（`--val-below` / `--val-within` / `--val-above` 及 `-soft`）。

- `ValuationBadge`、个股页标题徽章（`VerdictChip`）、结论带：击球区 = `--val-below` 实底（`-soft` 背景）；低于内在价值 = `--val-below` 描边；价值带内 = `--val-within`；高于价值带 = `--val-above`；待确认、未评估 = 中性灰（不变）。
- 实现：`valuationLabel` 的 `tone` 从 `positive | neutral | warn` 改为按档位的 `below | within | above | neutral`；`VerdictChip` 的 `Tone` 增加这三档并映射到 `--val-*`。原 `positive / warn` 只留给非估值用途。
- 筛选器、共识榜同样用 `ValuationBadge`，会一起变色——这是想要的“同一说法同一颜色”。

**13F 动作用字形，不用颜色。** ● 新建 ▲ 增持 ▼ 减持 ○ 清仓，文字用正文色。

- `MoveMark`（持有人表名字旁）：字形 + 字。
- `QuarterMovesLine` / `quarterMovesCounts`：每项前加字形。
- 投资人页四格：去掉绿色 / 红色数字颜色，标签前加字形；同时把“加仓 / 减仓”统一成“增持 / 减持”（第 2 步遗留的用词不一致）。
- 投资人页标题徽章“整体加仓 / 整体减仓”改中性色，前加 ▲ / ▼。

**不在本步：** 首页名言区块、HUD 角标（`.ticks`）、绿色等宽眉标（`tt-eyebrow`）、全站链接样式——这些留到申报季后。

## 四、原则核对

| 原则 | 本步怎么满足 |
|---|---|
| 精简 | 首屏一条结论带回答“贵不贵、谁在拿”；持有人数、本季动作、标尺各只出现一次（从原位置移走，不复制）；绿色只表达估值 |
| 不简单 | 方法与数字、价格在押注什么、生意质量、文字摘要全部保留，只是排在结论之后；折叠用原生 `<details>`，SSR |
| 信息准确 | 结论带只复用已有的计算与文案，不新增口径；估值颜色与 `valuationLabel` 同源；动作字形与股数口径一致 |
| 读起来轻松 | 新访客首屏看到价格在带的哪里和谁在持有；锚点导航一点即到；击球区进一级导航 |

## 六、测试与验证

- 纯函数 `.check.ts`：结论带的展示决策（有估值 / 未评估 / 拆股暂停 / SOTP 四种状态各显示什么）抽成纯函数测试；锚点列表（哪些区块有数据就出现）抽成纯函数测试；`valuationLabel` 的新 `tone`；`quarterMovesCounts` 带字形的中英文；投资人页名字行（新建 / 清仓、上限 3、另 k 只、无估值不写）。
- 渲染检查：用 `renderToStaticMarkup` 给 `StockConclusionBand` 和 `EarningsPowerFloorCard` 的 `part` 三种取值各做一个断言（summary 不含方法折叠、details 不含标尺）。
- 现有 `.check.ts` 全量重跑；`check:tokens`、`check:type`、`revalidate-paths` 检查通过。
- 预览核对：375px / 768px / 1440px × 中英文 × 深浅色，页面 AAPL（高于价值带）、PDD（击球区）、M（待确认）、BRK.B（控股公司）、一只未评估股票、巴菲特页、首页导航；确认无横向溢出，锚点跳转后标题不被顶栏挡住。

## 七、护栏

- 不新增 Supabase 查询；不改估值引擎和任何计算出的数字。
- URL、SEO 结构、SSR、结构化数据（JSON-LD）不变；埋点事件名不变。
- 零 hydration：不新增客户端组件（锚点导航纯 CSS sticky）。
- 中英文对等，各自核对 `docs/copy-voice.md`；合规只说位置和计数。
