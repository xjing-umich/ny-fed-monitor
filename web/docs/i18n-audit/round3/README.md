## 建议实施顺序与验收门槛

1. **批次A：含义与状态。** 先做上方1–8组，About来源随模型/数据说明同批补齐。需要改变统计分母或比较算法的事项，在落地前先明确契约；只修语言时保持原始历史数字不变。
2. **批次B：全站表达。** 统一估值术语、实体展示名、静态金额/季度/日期、表头、OG alt、中文标点和英文语法；中英文分别编辑，不机械逐句互译。
3. **批次C：交互与工程回归。** 手机长名称、排序方向、空搜索、Contact、404、语言查询与hash往返；同时补未发布动态报告的合成场景：缺前次申报、有申报但无变化、跨季比较。

完成条件应是逐条问题有对应线上证据；现有脚本只能作为补充。本轮 `check:i18n-format` 退出0（138个UI文件），`ai-check` 退出0（402段、0 hard/0 soft），但都未检出多项上述问题。无需将这两项通过写成全站验收通过。没有修改代码，因此未跑build或全量单测，也未创建提交、PR或部署。
