# 中英文案审核与提升方案（2026-10-27）

范围：`web/src` 下所有用户可见的字符串，包括 UI、SEO/OG、分享文案、邮件、估值说明、Learn 长文和季度报告。代码注释、日志和后端脚本不在范围内。
方法：按 5 个区域逐条审核，再做全站机械扫描（标点、术语频次）。分区明细见同目录下的 `A-brand.md` `B-investors.md` `C-stocks.md` `D-valuation.md` `E-learn-reports.md`，每条都附有可以直接替换的成品句。

## 一句话结论

中英文案生硬的原因不是用了 AI 套话，`npm run ai-check` 在黑名单上是全绿的。真正的原因有三个：

1. **写法**：先写好一种语言，再逐句译成另一种。长文是英文原稿、中文跟译；UI 是工程口径的中文，再直译成英文。
2. **没有术语表**：同一概念在全站有 6 到 7 种叫法。
3. **工程语言直接给了用户**：估值引擎的英文说明原样出现在中文页上，"口径""归并""对齐"这类词出现在首屏。

## 写作规范补充（追加进 `docs/copy-voice.md`）

**中文**
1. 全角标点：`，。：；？！（）`。中文里的引号统一用「」。
2. 中英混排时，中文和英文、数字之间留一个空格；中文词和中文词之间不留空格（不写「返回 学习」）。
3. 量词：人用「位」，股票用「只」，组合用「个」。
4. 少用「被」字句、「该/其」、「进行」、后置定语，也不要堆三个以上的「的」。
5. 不把英文口癖直译成中文：「名字」(name)、「被…得最广」(widely)、「只字不提」(says nothing about)、「一打」、「走出很远」。
6. 面向用户的文案不用工程词：口径、归并、对齐、切换、回填、降级、闸、引擎、信号（当名词用时）、基准季、覆盖率、可估值。

**英文**
1. 句首大写（sentence case）：只有标题第一个词和专有名词大写，不写 "Stay Updated"。
2. 不写缩写和内部代号：Prev 改成 Previous，不出现 v1、lamp、AV_conservative。
3. 美国读者不认识的自造术语，要换成通行说法或第一次出现时解释：value band、co-holding signal、Lonely conviction、posture、Position 列。

**流程（最关键的一条）**
- **两种语言各写各的，不互相翻译。** 写中文时假设读者从没看过英文版，反过来也一样；两版只需要表达同一件事、用同样的数字。长文先定"要点和数字"，再按两种语言各自的论证顺序写。
- Learn 文章不再在结尾统一写"以上不是投资建议，判断留给你"，这句交给页面组件，固定显示一行。

## 需要你拍板的 4 项

1. **句中泛称用「投资人」还是「投资者」**：我建议用「投资人」，更口语，指具体的人时也更自然，报告和 Q2 文章已经在用。代价是要改大约 110 处「投资者」，第 1 批脚本可以一并处理。
2. **「价值带」要不要改成「价值区间」**：我建议改。读者不用解释就能看懂，也更符合"精简·轻松"。代价是这是一个已经用开的站内概念（中文约 37 处）。英文无论如何都要从 value band 改成 value range。
3. **英文「Consensus」导航要不要改成 "Most widely held"**：美国读者看到 consensus 会先想到分析师一致预期。我建议改，中文保留「共识持仓」。
4. **中文正文要不要统一用中文公司名**（微软、苹果、亚马逊）：我建议要。

另有两处 `legal.ts` 的修改涉及法律含义（"归本站所有"改为"归运营者所有"，以及"按'现状'和'现有'基础提供"的改写），**需要律师确认后再改**。
