# 国际化专业度审核 · 第二轮（2026-10-28）

**问题**：我们的中英双语，在专业读者眼里够不够专业？
**对标**：中文读者按雪球、华尔街见闻、富途/老虎、券商研报、Wind 的习惯来读；英文读者按 Bloomberg、WSJ、Morningstar、WhaleWisdom、Dataroma 和 SEC 原文的习惯来读。
**范围**：首页与全站外壳、股票列表与选股器、个股详情（估值区单独审）、投资者列表与详情、买卖榜与共识榜、Learn、法律页，以及工程层的 i18n 和格式化。
**口径**：本地站跑的是 `db-foundation` 57a6aa3（已含 #233、#235）。13F 数据是 2026 Q2（截至 6 月 30 日），股价是 2026-10-27 收盘，10 年期美债收益率是 FRED 2026-10-23 的 5.00%。
**分工**：5 个方向并行审核，分区明细在本目录 `1-` 到 `5-` 文件，每条都有 URL 和 file:line。下文的 P0 和关键 P1 都经过抽查复核，核对方法写在第 6 节。
**原则**：第一轮（上一级目录 `README.md`）报过的问题这里不再重复；第一轮判断有误的地方，在第 4 节单独更正。

## 1. 结论

| 区域 | 中文 | 英文 | 一句话 |
|---|---|---|---|
| 首页 / 外壳 / Learn / 法律 | 2.5 | 3.5 | 首屏的数据层仍然是英文数据站的写法 |
| 股票列表 / 选股器 / 个股（不含估值） | 2 | 3 | 「市值」有歧义，人名三套写法，股价取整 |
| 个股估值区 | 2 | 3 | 同一张卡上数字和名字对不上，术语有几处贴错对象 |
| 投资者 / 买卖榜 / 共识榜 | 2.5 | 3.5 | 13F 术语和读者习惯错位，金额口径没有标注 |
| 工程层 / 格式化 | 3 | 4 | 骨架是对的，但数字怎么写这一层完全没有本地化 |

**总评：中文约 2.5/5，英文约 3.5/5。**

做得对的部分：
- `<html lang>`、canonical、成对的 hreflang 加 x-default、og:locale 全部正确。
- 负号统一用 U+2212，中英混排的空格约 96% 一致。
- 首屏的一句话结论已经写到专业水准。
- 第 0 批修完以后，不再有明显的翻译错误。

拉低专业感的是三层，按影响从大到小：

1. **数字的写法没有本地化（覆盖面最大）。** 全站调用 `Intl` 的地方是 0 处，`formatUSD` 和 `quarterLabel` 都不区分语言。抽样的 12 个中文页里有 403 处 `$X.XB/M`、79 处 `Q2 2026`、111 处 ISO 日期，没有一处用「亿」或「年月日」。中文读者看到的是「英文数据站套了一层中文标签」。
2. **几处会让专业读者质疑数据的问题（伤害最大）：**
   - 估值卡上同一个数字有两个名字，三个不同的数字都叫「零增长」。
   - 「市值」在中文语境里会被读成公司总市值。
   - 买卖榜的金额没有标注，读者会读成"买入金额"。
   - 股价取整到美元，$2.88 显示成 $3。
   - 选股器页头标的是计算任务的日期，不是行情日期。
3. **金融术语和读者习惯有错位**：
   - 13F 的动作四件套用词。
   - 「10 年期国债」在中文里默认指中国国债。
   - ADR 的估值按每 ADS 算，单位却写「/ 股」。
   - 银行估值用了「重置价值」。
   - 中文「净流动资产」和格雷厄姆的 NCAV 不是一回事。
   - 公司名和人名的清洗、译法不统一。

## 3. 格式化：一次基础设施改动，覆盖面最大

**现状**：
- `formatUSD` 被调用 26 处，`quarterLabel` 42 处，估值卡里自写的 `usd/usd0/perShare/range` 约 40 处，选股器里还有内联的 `Math.round(...).toLocaleString()`。
- 精度有三套：B 档两位小数、M 档一位小数、低于 100 万退回全额美元。
- 有 9 处 `toLocaleString()` 没传 locale，输出会随访客的系统语言变化，还可能引起 hydration 不一致。

**目标格式**（建议定稿，Intl 的实际输出已在 Node 里验证过，见 5-engineering §4.3）：

| 类型 | 中文（zh-CN） | 英文（en-US） |
|---|---|---|
| 大额金额，正文和卡片 | `1.62亿美元`、`768亿美元` | `$162M`、`$76.8B`（3 位有效数字） |
| 大额金额，表格 | 单元格写 `1.62亿`，表头写「持仓市值（美元）」 | `$162M`；低于 100 万写 `$964K` |
| 现价 | `$347.62`；正文写「347.62美元」 | `$347.62` |
| 每股估值 | 「每股 254 美元」；紧凑位置写 `$254`，表头写单位 | `$254/share`；ADR 写 `$346/ADS` |
| 股数 | 「2.28亿股」，表头写「持股数（股）」 | `227,917,808` |
| 日期，正文和来源 | `2026年6月30日` | `June 30, 2026` / `Jun 30, 2026` |
| 日期，密集表格 | `2026-06-30`（Wind 的写法） | `Jun 30, 2026` |
| 季度，标签 | `2026Q2`（全站统一一种） | `Q2 2026` |
| 季度，正文 | 「2026年二季度」 | "the second quarter of 2026" |
| 区间 | `$76–$158`，en dash，两侧不加空格 | 同左 |
| 极小占比 | `<0.1%` | `<0.1%` |

**落地方式**：
- 新建 `src/lib/i18n/format.ts`，提供 `money`、`price`、`shares`、`pctDelta`、`date`、`quarter`、`range`，locale 写死成 `zh-CN` 或 `en-US`，日期按 UTC 处理。
- 旧函数先改成薄包装，再分批替换调用点。
- `ai-check` 加防回退规则：禁止不传 locale 的 `toLocaleString()`，禁止拼出 `` `$${…}[MBT]` ``。

注意三个坑：
- zh 的 compact 默认只保留 2 位有效数字，会输出 "1.6亿"，必须设 `maximumSignificantDigits: 3`。
- zh 的货币样式会输出 `US$1.62亿`，不是媒体写法。
- 负号是 ASCII 的 `-`，要换成 U+2212。

**工作量**：约 1.5–2 天。可以和第一轮计划里的"第 1 批机械统一"合并做。
